### presets-side-by-side: keep, with a corrected source

The picture helps under "The settings of each preset": the section gives numbers, and four tiles show how much the look changes.

What is wrong:
- "Same capture as on the tables page" is not a step.
- The island is the wrong scene. Its sketch (examples/showcase/island/sketch.ts) keeps the physical sky on every preset, turns bounce light off, pins the render scale at 1, sets anisotropy to 16x, and turns the governor off on High and Ultra. ### stats-overlay-governor: reject

- The stats overlay does not show the governor's steps. Its heading shows only the GPU tier, the preset and the render scale (packages/engine/src/debug/overlay.ts). The Steps tab lists add-on features and timed GPU passes, not governor steps. The alt text would be false.
- The steps do not work. `?fps=` holds a fixed frame rate and caps the target at that rate (packages/engine/src/render/pacer.ts, packages/engine/src/quality/check.ts). A high value does not make the governor step down. No switch forces a governor step, so the capture cannot be repeated.
- The forest demo has nothing of the governor to show. It only refits its counts when the preset is Low (examples/forest/planting.ts).

## Demo links

### The governor on a heavy scene -> forest/: reject

The code exists (examples/demos.ts, `code: 'forest/'`). But the forest sketch does nothing with the governor. Its `quality.onChange` handler refits the tree counts only for the Low preset, so a governor step changes nothing in its code. A reader who opens it under "The frame-budget governor" finds no governor. No demo calls `setBudget` or reads `quality.governor`. Leave the section without a demo link.

### Moment transparency -> showcase/island/: keep

The code exists. The island is the only demo that starts with moment transparency (`momentTransparency: true` in examples/demos.ts, passed to `createEngine` by examples/lib/run.ts). Its sea draws blended surfaces (examples/showcase/island/sea.ts). The section itself quotes the island's memory figures, so the link matches the text.

### Hold mode -> hold-mode/: reject

The link is valid: the demo has no `code`, so `hold-mode/` is right. But the section "Starts that crashed the tab" only says that hold mode leaves the crash note alone. The demo shows repeatable frames of bouncing balls; it shows nothing about crashes or presets. Hold mode belongs to the testing docs.

### New: a table keyed by preset -> galaxy/: add

The page's first code example keeps a count per preset in a table and refits it in `quality.onChange`. examples/galaxy/sketch.ts does exactly this (`DRAWN[quality.preset]`, then `quality.onChange(fit)`). Link https://github.com/null3d-engine/null3d/tree/main/examples/galaxy/ under that example. examples/instances/sketch.ts does the same with its rows.

### New: switching presets from a menu -> showcase/creek/: add

The showcase scenes have a Quality menu that calls `quality.setPreset` and greys out presets above `quality.highest` (examples/lib/showcase-effects.ts, examples/lib/controls.ts). Link https://github.com/null3d-engine/null3d/tree/main/examples/showcase/creek/ under "Switching presets".
