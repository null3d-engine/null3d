The memory is flat, and that is this run's finding. The WebAssembly memory, the GPU's texture bytes and the GPU's buffer bytes are the same at every reading, to the byte, across the hour: 41,025,536 bytes of WebAssembly memory, 512,124,518 of textures and 18,664,653 of buffers. A gate's Rust build ran on this Mac from 11:59 to 12:13, inside the run's first three windows, and the load rose to 26 across the third; none of the three figures moved through it, which makes the flatness stronger evidence than a run on an idle machine alone. The JavaScript heap moves between 49.2 and 134.8 MiB with no trend, which is a collector's work and not growth.

The frame figures are not this run's evidence, and the reason is in its own numbers. The first two windows drew for the whole 300 seconds: their interval samples cover every frame they counted. From the third window the page counted about 6,000 frames in each 300 seconds, and those frames' intervals cover only 60 to 100 seconds of it, with medians of 8.3 to 9.0 ms. So the page stopped drawing for long stretches of those windows. The Mac's load was not the cause: it read 4 to 8 through the second window, rose to 26 for five minutes across the third, and then fell to 3 to 6 for the rest. The runner met the same fault later in the day and named it: Chrome reported its window hidden, so the page got no animation frames. What was missing here is that nothing kept the window visible: the runner parked it, which is enough while the display stays awake, and no flag stopped Chrome throttling a window it counted as hidden. A later soak of this kind needs the display kept awake, or a Chrome flag that disables occlusion throttling, and the record names the lack because it costs an hour to discover.

So the only windows this run may speak for are the first two, and they speak of their own frames alone. Window 1's worst frame is 218.8 ms, a stall in the minutes just after the first frame while pipelines are built. Window 2's worst is 47.3 ms. Neither window answers the 50 ms clause, and this record does not use them to.
