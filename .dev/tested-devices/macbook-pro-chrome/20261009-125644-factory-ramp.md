Plans: Factory's ramp, the first run of the comparison with three.js, from the branch of M2-EX5 ([D-121](../../decisions/D-121-comparison-tier.md#first-figures))

Result: 5 ramps, each to its maximum of 50,000 moving parts at 1280 x 720 CSS pixels, pixel ratio 1, every effect on, in a Chrome 155 window that Playwright opened on the Mac's GPU (Apple M5 Max). The window presented 60 frames a second, not the display's 120, so these are 60 Hz figures.
Every engine held 50,000, the top of the ramp, so the ramp showed no gap. The busiest thread's CPU time per frame at 2,000 and 50,000 moving parts:
- null3D on WebGPU, High: 1.81 and 3.17 ms. The 1-minute load was 6.1.
- three.js WebGPURenderer: 4.88 and 6.63 ms. Load 5.4.
- three.js WebGLRenderer on a WebGPU device: 0.51 and 1.58 ms. Load 9.9.
- null3D on WebGL2, Medium: 2.09 and 5.00 ms. Load 22.1, so this figure is not a timing.
- three.js WebGLRenderer: 0.65 and 1.69 ms. Load 18.6, so this figure is not a timing.
