Which pass owns it. The profile run is `20261014-060504-ao-calls-sync`. It ran on the iPhone 18
Pro with Safari 27.0 and tree origin/main `114a1246d`. The plan is `ao-calls-sync`. That plan sets
`gl-timing=sync`.
The render worker spends 4.48 ms a frame with ambient occlusion on. Its `clear` calls take 4.07 ms
over six calls a frame, against 0.20 ms over two calls with ambient occlusion off. The three added
clears belong to the ambient occlusion passes `AoDepth`, `AoHorizon` and `AoDenoise` (frame graph
`AO_PASSES`). Each creates and clears a target at half the render size. A sync profile's first
value-returning call after a pass absorbs that pass's GPU time. So the profile places the cost in
those three passes rather than in one call. The cost stays the same at render scales 1 and 0.5.
The AO targets shrink with the render scale. So this fits a fixed wait on the GPU process for each
pass on Safari 26.6 and later. It does not fit the passes' pixel work.
