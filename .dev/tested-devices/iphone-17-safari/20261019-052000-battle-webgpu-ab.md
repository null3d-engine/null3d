Plans: Battle's page eight times in one session, 2026-10-19, on the working tree of `perf/battle-webgpu` with local probe hooks only, in Safari 26.5 (iOS 26) on the iPhone 17, screen at 60 Hz. The page was `examples/index.html?compare=battle&engine=null3d&gpu=webgpu` at 100 units, 603 x 1009 backing pixels at a pixel ratio of 1.5, on the direct path, with 15 seconds of warm-up and 8 seconds of the page's own measure. The pages alternated the default with a probe that set the sun's shadow filter to 5, then the default with `?skinning=compute`.

Result: eight pages measured, none failed.

| Page | Presented fps | GPU time | Draws |
| --- | --- | --- | --- |
| Default, first page of the session | 25.1 | 29.90 ms | 298 |
| Sun filter of 5 | 29.7 | 24.32 ms | 267 |
| Default | 30.0 | 23.81 ms | 266 |
| Sun filter of 5 | 29.5 | 24.67 ms | 265 |
| Default | 29.8 | 24.06 ms | 266 |
| The skinning pass | 27.1 | 25.36 ms | 1,238 |
| Default | 28.5 | 25.63 ms | 265 |
| The skinning pass | 27.3 | 26.04 ms | 1,238 |

The first page of the session is about 5 ms slower than the pages after it with the same settings, which explains the apparent savings of the earlier pages. Warm, the shadow filter's square changes nothing, and the skinning pass is slower while drawing four times as many draws. So no engine default changed ([D-20](../../decisions/D-20-webgpu-skinning.md#addendum-2026-10-19-the-pass-measured-on-an-iphone-17-and-why-it-is-not-a-default), [D-169](../../decisions/D-169-anti-acne-plane-cost.md#addendum-2026-10-19-the-filters-square-on-an-iphone-17-and-a-cold-first-page)).

On the same device in other sessions of the day, three.js's WebGPURenderer held 30.8 and 31.4 frames a second on this page, so the warm gap between the engines is about one to three frames.
