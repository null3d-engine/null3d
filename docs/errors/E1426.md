# E1426: Pointer lock with input off

## What happened

engine.requestPointerLock() asked for the pointer lock on an engine started with input: false. The lock is part of the engine's input: the sketch reads the mouse's movement through the engine's listeners, which that option turns off. So the engine takes no lock, and leaves the lock to the code that records the page's input.

## How to fix it

Lock the pointer through the code that records the page's input, which reads the mouse's movement: call canvas.requestPointerLock() there. Or start the engine without input: false, so that the sketch reads the movement through engine.requestPointerLock().

[Where problems appear](../guides/debugging.md#where-problems-appear) says where each kind of error reaches your code.

## Example message

The engine prints the part below, then the fix above and a link to this page.

```text
E1426: engine.requestPointerLock() was called on an engine started with input: false, which reads no pointer movement.
```
