# E1416: glTF file not read

## What happened

assets.loadGltf() could not read a file as a glTF 2.0 model. The file is broken, it goes past a limit of the engine, or the rewriteUrl option refused an address that it names. The message names the part that failed.

<details>
<summary>Technical details: the limits for one model file</summary>

- A broken file: a broken JSON or binary chunk, an offset or count past the data, a missing buffer or image, a node loop, a skin or clip that breaks glTF's rules, or Draco data that does not decode to the counts its accessors give.
- Decoded data for one file: 64 MiB, plus 32 bytes for each byte of the file and its buffers, up to 1 GiB. A block of meshopt data counts too.
- One array: 256 MiB.
- Nodes moved by skins and clips: 1,024.
- Keys in one clip, its frames times its tracks: 4,194,304.
- Sides of one PNG or JPEG image: 4,096. Decoded images: 1 GiB.

</details>

## How to fix it

Check that the file is a glTF 2.0 model: a .glb file, or a .gltf file with its buffers and images beside it. For a broken file, open it in the Khronos glTF Validator and export it again. For a skeleton that is too large, export each character to its own file. For a file over a size limit, split it or simplify its meshes.

[Where problems appear](../guides/debugging.md#where-problems-appear) says where each kind of error reaches your code.
