# E1220: Invalid render pass

## What happened

A render pass call got options that it does not take, or a pass of a kind that it does not work on. The message names the call and the rule that it breaks.

<details>
<summary>Technical details: what each render call refuses</summary>

`render.addPass()` refuses an unknown kind or option, no camera, and a size outside 1 to the largest texture. It refuses both a size and a scale, an unknown input image, and a workgroup size or dispatch that a device cannot run.

It refuses a format that a compute pass does not write, and a compute pass on WebGL2 with no fallback. It refuses a texture name or pass name that another pass has, and a 32nd live pass, since at most 31 passes draw at once.

`textures.fromPass()`, `render.setPassEnabled()` and `render.removePass()` take any render pass. `render.setPassUniform()` takes a full-screen pass, and `render.setPassUniforms()` takes a compute pass and at most 32 numbers.

</details>

## How to fix it

Give render.addPass the options of its kind, such as { kind: 'scene', camera, writes: 'minimap', size: [256, 256] }. Give a compute pass a workgroup size that the shader declares and that a device runs, and a fallback for WebGL2. Give each pass a name and a texture name of its own. Remove passes that no longer draw before you add more.

[Where problems appear](../guides/debugging.md#where-problems-appear) says where each kind of error reaches your code.

## Example message

The engine prints the part below, then the fix above and a link to this page.

```text
E1220: render.addPass() got writes "minimap", which the pass "minimap" writes already. Give each pass a texture name of its own.
```
