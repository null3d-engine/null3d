# E1501: Render space full

## What happened

The scene needs more room than the renderer has. The message names the full part, such as the material table, the texture table, the culling pass or the shadow atlas. A frame that fails draws nothing, and the canvas keeps the last whole frame.

<details>
<summary>Technical details: each full part and its limit</summary>

| Full part | Limit |
| --- | --- |
| Material table | The message says it is full. |
| Draw list | The megabytes that its commands may take, which it reaches only when memory runs out. |
| Culling pass | 2,097,152 objects and instance rows on WebGPU, and more on devices with larger GPU buffers. On WebGL2 the number follows the largest texture. `engine.capabilities.maxInstances` gives the device's number. |
| Skinning on WebGPU | 8 GPU buffers, 1 GiB in all on most devices, and 32 mesh pages. |
| Views | 32, the camera's included. |
| Shadow atlas | 1,024 MB. |
| Texture table | The message says it is full. |
| Upload space | The room that the frame sets aside. |
| One GPU buffer | The bytes that one GPU buffer may take on the device. |
| Rectangle lights | The most lights that show images at once. |
| Light image size | The texels a side that an image takes. |

</details>

## How to fix it

Share meshes, materials and textures between objects instead of creating them per object. Draw many copies of one mesh with an instance batch, and size each batch for the rows it uses. For a large crowd of skinned characters on WebGPU, use models with fewer vertices or fewer copies. The crowd draws again once it fits.

- For the culling pass: every row of a batch counts toward the limit, active or not, so size each batch for the rows it uses.
- For skinned characters on WebGPU: each copy skins its own vertices, even when copies share a mesh.
- For the shadow atlas: name a smaller `heroTileSize` or fewer `shadowTiles`.
- For the views: destroy views that no longer draw.
- For the texture table: use fewer textures, and share them.
- For the upload space, the draw list or one GPU buffer: make that part smaller. The message gives the megabytes or bytes that it may take.
- For rectangle lights or a light image: show images on fewer lights, or use a smaller image.
