# E1424: Custom shader builds not downloaded

## What happened

A file that holds a custom shader's builds did not download, so the engine draws no new frames. The server answered with an error, sent another file in its place, such as a web page, or the connection broke off.

<details>
<summary>Technical details: the shader build files</summary>

The null3D Vite plugin builds each custom material, effect and tone curve for every GPU path. It puts the builds in files of their own beside the sketch's files.

A material's files are named material-*.js: one for each GPU path and each set of builds that the device fixes. Those sets hold the builds that tone map or skin. An effect's and a tone curve's files are named effect-*.js and curve-*.js: one for each GPU path.

A page downloads its device's file when the sketch first uses the shader. It downloads another material file when a pipeline needs one, such as the builds that skin for the first skinned mesh.

</details>

## How to fix it

Deploy every file that the build wrote, the material-*.js, effect-*.js and curve-*.js files among them, from one build, and serve them as JavaScript at the paths that the build gave them. A strict Content-Security-Policy must allow them in its script-src. On the dev server, reload the page. After a failure during play, destroy the engine and start a new one.

[Where problems appear](../guides/debugging.md#where-problems-appear) says where each kind of error reaches your code.
