# E1110: Unmarked write to a static object

## What happened

A static object's position, rotation, scale or bounding sphere changed without a setter. The engine updates a static object only in a frame where a setter marks it or its parent moves. A row of a static instance, sprite or point batch that changed without `markDirty()` raises it too.

<details>
<summary>Technical details: when the check runs</summary>

The change can show late, or never. Development builds check for these writes in every frame. Release builds leave the check out, so no error comes, and the picture can stay wrong.

</details>

## How to fix it

Change a static object with setPosition(), setRotation(), setScale() or another setter: each one marks the object for the engine to update. Code that writes values straight into engine memory needs a dynamic object, which the engine updates in every frame. For a row of a static batch, call markDirty(start, count) on the batch after you write its arrays, or create the batch with dynamic: true. If your code writes no engine memory, this is an engine bug: report it with the message.

Report engine bugs on [GitHub Issues](https://github.com/null3d-engine/null3d/issues). Add the full message and [engine.report](../guides/debugging.md#how-the-engine-runs-on-this-device).

[Where problems appear](../guides/debugging.md#where-problems-appear) says where each kind of error reaches your code.

## Example message

The engine prints the part below, then the fix above and a link to this page.

```text
E1110: the position of "Crate" (slot 7) changed without a setter.
```
