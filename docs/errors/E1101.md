# E1101: Stale handle

## What happened

A call used an object after it was destroyed. Its slot may already hold a new object.

## How to fix it

Stop using an object after you call destroy() on it. Look for places that still keep a reference, such as arrays of enemies or selection state.

## Example

```text
E1101: setPosition() was called on "Crate" (slot 7), which was destroyed in frame 120.
```
