# E1206: Invalid mesh arrays

## What happened

A call that builds or updates a mesh, a line or a set of points got arrays that do not fit. An array can have the wrong length, an index can name no vertex, or a value can be NaN or Infinity.

<details>
<summary>Technical details: what each call checks</summary>

| Call | Refuses |
| --- | --- |
| `geometry.fromArrays()` | an array of the wrong length, an index past the last vertex, a NaN or Infinity value, missing normals, normals both given and computed, both `targets` and `morphTargets`, and no indices with a vertex count that is not a multiple of three |
| `scene.createLines()` | fewer than 2 points, an odd count for segment pairs, and colors that do not match the points |
| `scene.createPoints()` | no points, and colors that are not 3 or 4 numbers per point |
| `mesh.updateVertices()` | an attribute that the mesh lacks or that takes no updates, another array type than the mesh keeps, an array that does not hold every vertex, vertices past the last one, a mesh with joints or morph targets, and a start or count that is not a whole number of 0 or more |

</details>

## How to fix it

Give positions and normals three numbers per vertex, uvs and uvs1 two, colors three or four, and tangents four. Give three indices per triangle, each below the vertex count, or no indices and a vertex count that is a multiple of three. Pass normals or `computeNormals: true`, and pass uvs with `computeTangents: true`. Replace NaN and Infinity values.

- For `mesh.updateVertices()`: give values for every vertex, in the array type that the mesh keeps, for an attribute that the mesh has.

[Where problems appear](../guides/debugging.md#where-problems-appear) says where each kind of error reaches your code.

## Example message

The engine prints the part below, then the fix above and a link to this page.

```text
E1206: geometry.fromArrays() got 9 numbers in normals for 4 vertices, not 12.
```
