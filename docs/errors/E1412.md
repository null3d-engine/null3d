# E1412: Asset not decoded

## What happened

A loading call downloaded its file but could not read it. The message says what in the file the engine could not read, with its line where it has one.

<details>
<summary>Technical details: the files that the readers refuse and their limits</summary>

- An image that the browser cannot decode, such as one in a format that it does not support.
- A KTX2 file that the engine does not load.
- A file that is not valid JSON.
- A color grading table that the engine does not read, such as a 1D table or one with a texel missing.
- A file that is not an environment map that `bunx @null3d/cli assets env` writes.

A KTX2 file fails before it transcodes when it is wider or taller than `textures.maxSize`, or holds more than 256 layers. It also fails when it holds more mip levels than its size has, or texels of more than 256 MiB.

A PNG, JPEG, WebP or AVIF file fails before it decodes when its header gives a side longer than `textures.maxSize`, or longer than 16,384 for `assets.loadImageBitmap()`.

</details>

## How to fix it

Give `loadTexture` and `loadImageBitmap` a PNG, JPEG or WebP file, or an AVIF file in a browser that decodes AVIF. Give `loadTexture` KTX2 files of 2D ETC1S or UASTC data, as basisu writes them. Give `loadJson` valid JSON, and check that the server sends the file itself, not an error page. Save KTX2 textures no larger than `textures.maxSize` on each side.

[Where problems appear](../guides/debugging.md#where-problems-appear) says where each kind of error reaches your code.

## Example message

The engine prints the part below, then the fix above and a link to this page.

```text
E1412: assets.loadTexture() could not decode https://example.com/tex/brick.tga as an image: The source image could not be decoded.
```
