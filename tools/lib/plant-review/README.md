# Plant review tools

`bun run plants:review` puts a species beside every reference file it has, view by view and frame by frame, and measures how far apart the two are. It writes contact sheets, the measures as JSON, a short summary and a coverage list. The coverage list names each reference file in use and the render it was compared with. The owner's rule is that a species passes only when every reference file in use has a comparison, so a file without one blocks a pass.

The tool reaches the plant core through one page: the plant review sketch, `tests/pages/sketches/plant-review-sketch.ts`. Its query contract and its views are in `tests/pages/lib/plant-review/`. The page grows the species through the plant core's public functions, so it draws what a scene would draw. The tool only builds queries and reads pixels.

## What you need

- Google Chrome, and ffmpeg with ffprobe.
- A dev server for this copy of the repository on its own port, for example `NULL3D_PORT=6361 bunx vite --port 6361 --strictPort`. The first start builds the shaders, which takes several minutes. The tool reads the port from `NULL3D_PORT`, starts a server when none answers there, and refuses a server that serves another copy.
- The species' reference folder. By default the tool looks for it under `.internal/coordination/tree-corpus/generated/<species>`, or under the folder that `NULL3D_PLANT_REFERENCES` names. `--refs` names another folder, or another slug.

## Worked example

This reviews the stub stand-in against the pedunculate oak's references and writes the run into a folder of your choice.

```sh
export NULL3D_PORT=6361
bun run plants:review stub --refs pedunculate-oak --out /tmp/plant-renders --run oak-1
```

The species is any registered species id, or any other id, which draws as a stand-in. A registered species draws through its real stages. Any other id draws the stand-in of every stage. `--views all` adds one picture of every view, with no reference beside it.

The run folder holds:

- `stills/`: one render of each still and texture source in use, with its camera, framing and background matched to the picture, and a matte for those whose outline is compared.
- `turn-<video>/`: one render for every frame angle of each turning video, round a full circle, with a matte each. The renders are drawn as sheets of cells in one page and cut apart.
- `wind-<video>/`: the whole plant in the default wind, framed as the wind video frames it, eight frames a second by default.
- `views/`: the views that `--views` asked for.
- `manifest.json`: the commit, the species, the references, and each frame's query, hash, time and the facts the page posted, its measures among them.
- `sheet-*.png`: the contact sheets. The still sheets show each reference, its render and their outline overlay in a row. The turn and wind sheets show a grid of tiles: the reference frame over the render matched to it, then the outlines.
- `metrics.json`, `summary.md`, `coverage.json` and `coverage.md`.
- `verdict.json`: the run's verdict for each of the twelve rows, which `bun run plants:ledger` counts.

Look at the sheets first. In an outline overlay, the reference is magenta and the render green, and grey is where both have plant.

## Options

| Option | Use |
| --- | --- |
| `--refs <folder or slug>` | The reference folder; the species' own slug by default. |
| `--out <folder>`, `--run <name>` | Where the run goes, `.internal/coordination/tree-renders/` and `<species>-<time>` by default. |
| `--only stills,turns,wind` | Draw only some kinds of reference. The coverage list then names the rest as not drawn. |
| `--step <degrees>` | Draw a turn's renders this far apart rather than at every frame's angle. A quick look; the frames between renders do not count as covered. |
| `--wind-fps <n>` | Frames a second of the wind clip; 8 by default. A clip counts as covered when it spans the video at this rate. |
| `--cell <pixels>` | The width of a turn's or a wind clip's frame; a still's width by default, so a video's frame is drawn and measured as a still is and takes the same detail level. |
| `--views a,b` or `--views all` | Pictures of views with no reference. |
| `--seed`, `--variant`, `--preset`, `--gpu` | The plant, the mesh tier, and the GPU path of the image page. |
| `--slot-query <file>` | Page query fields per reference file, from a JSON object keyed by the file's name, laid over each still's or video's own query: for example a camera its picture needs, or the light it was taken in (`sunAzimuth`, `sunRise`, `skyShare`, the sky's share of a sunlit view's light, and `daylight`, that light's strength). A field given as `null` is dropped, so a still can trade the framing's `fill` for a `top` row and an `eye`. A video's entry goes over the framing and the light measured from its frames, so it can replace either. `barkMask` measures a close view or a texture source on the plant alone, so a backdrop does not dilute its colour. `leafyBark` measures a bark close view on the bark alone: leaf-green pixels leave the patches on both pictures, so foliage across a limb does not read as the bark's colour. `noOutline` declares a picture whose own background is the subject, such as a far scrub band that the fitted sky and ground admit: the picture carries no outline, so its shape, width, gap, crown box and pieces read null while its colour stays. The reserved key `_sheath` names a species' sheath target for the sheath figure: an Rgb read at both ends, or an object with `foot` and `collar` Rgb colours and a `reach` share of the surface's top, all from 0 to 1. A species' own file is `slots/<species>.json` beside this guide, such as `slots/pedunculate-oak.json`. The run reads no file unless this flag names one, and it warns when a species' file exists and the flag is absent. Draw both sides of a comparison with it. |
| `--no-matte` | Skip the mattes; outlines then come from colour. |
| `--compare <run folder>` | Compare an existing run again, without drawing. |

The command's status says whether the run did what it was asked. A run asked for a part of the references, with `--only`, `--stills` or `--views`, ends with status 0 when every picture it asked for drew and was compared, or was drawn for the eye. It ends with status 1 when a frame failed, or when a picture it drew gave no figure where its view has one. A run of every reference ends with status 1 when a frame failed or the coverage is not complete. Whether the species is complete is the ledger's count, never a part-run's status.

## The references

`references.ts` reads the folder's `INDEX.md`. A row whose "what it shows" cell says the file is superseded takes the file out of use, and so does a row whose later cell says "Superseded by" a file. Every other picture and video is in use, listed or not, apart from videos' contact sheets.

- Numbered stills go to the review view that shows the same thing, by the words in their names first and their numbers second. A still of another habit or a young form goes to the nearest view.
- A still whose name names one of the species' other forms, such as `young` or `woodland`, is drawn in that form: the tool reads the forms from the species' record and gives the still's query the `form` field. An index row's words never pick a form, since a row can name another form in passing, and a texture source never takes one. Where the record has no such form, the still is drawn beside the grown plant, with a note.
- A still is drawn in the season its name gives: flowers in blossom, fruit in autumn, a bare plant in winter. A still of fruit whose picture shows more green than autumn colours is drawn in summer, since its leaves have not turned.
- Texture sources (24 to 28) go beside the render's own surface: the leaf faces, the bark at mid-trunk, and young bark far out on a limb. The bark close-ups stand in the copy-stand light, which follows the camera, so a turned view still shows the surface as its albedo. The bark views frame the metres that the species' texture manifest gives, or the metres that the slot's own query names.
- `*-turntable*.mp4` is a turning video of the whole plant, or of the branch, sub-branch or leaf cluster that its name gives; `-halfturn` covers 180 degrees.
- `*wind*.mp4` is a wind video.
- A video's renders are framed and lit as its frames are: the framing, the colours and the light are measured from eight of its frames. The light is read against each frame's camera, and the median is kept. The reference videos keep their light where their camera is while the piece turns, so each sheet of a turn stands its one sun as that light stands to the sheet's middle turn. A sheet with a measured light spans at most 30 degrees of the turn, so every cell's camera stands within 15 degrees of where the light was read from.

## The page's query

`plantReviewQuery` in `tests/pages/lib/plant-review/query.ts` builds the query and `readPlantReviewQuery` reads it. Shares count from the frame's left edge and down from its top edge, from 0 to 1.

| Field | Meaning |
| --- | --- |
| `species` | A species id. |
| `form` | One of the species' other forms, such as `young`; the record as it stands by default. A record without that form grows as it stands, and the page notes it. |
| `variant`, `seed` | The plant's variant and seed; 0 and 11 by default. |
| `view` | The view; `whole` by default. `views.ts` lists them with their reference slots and defaults. |
| `turn`, `elevation` | Degrees round the plant (0 looks from +Z) and above the view's target. |
| `distance` | Metres from the camera to the view's target, in place of the fitted distance. |
| `fov`, `size` | The vertical field of view, and the frame's size, which gives its aspect. |
| `background`, `sky`, `ground` | `sky-meadow`, `studio-grey` or `white`, and sRGB colours in place of its own. |
| `sun` | `default`, `low`, `back`, `overhead`, `flat` or `albedo`. |
| `sunAzimuth`, `sunRise`, `skyShare`, `daylight`, `lamp` | A view's light as its reference was lit: the sun's degrees to the camera's right and above the horizon, the sky's share of the light, the light's strength, sky, sun and ground bounce together, as a multiple of the page's soft daylight (1 by default, up to 8), and a lamp colour in sRGB hex for a studio picture whose photograph has its own white balance; the strength reaches a studio's fill and copy stand as well as the sun. A clear sky lights a plant more brightly than the soft daylight does against the same sky colour. A review measures the strength from each photograph's own sky: a calibration to the picture, not a derivation from physics, since a photograph's tone curve squeezes a bright sky more than the plant. To fit a cut piece's strength, draw it at several and compare the mean's rise with the light's: a tone curve shows as a mean that rises more slowly than the light. Where it rises with it (the olive's foliage did within five per cent from 1.6 to 2.88), set the strength that matches the photograph's own mean and keep that figure; a lower strength that colours better is a fit and will not hold on the next picture. |
| `wind`, `time` | The wind's strength from 0 to 3, and the wind clock's time, at which the tool holds the frame. |
| `season`, `lod`, `preset` | The season, a level forced at every distance (0 to 3), and the mesh tier. |
| `pick`, `cut` | The cutting candidate and its length in metres. |
| `cutFrom`, `cutSpan` | Metres along the axis where a spanned piece starts, and the metres it keeps, in place of the record's hint: a close still may show the frond's base or its middle, as its photograph does. |
| `measure`, `scale`, `matte` | Post the measures; draw a 1 m bar; draw the plant black on white. |
| `meadow` | Stand a cut piece on the meadow, laid at the piece's own foot, as a photograph of one frond standing alone in its field shows it; a cut piece otherwise stands on its background alone. |
| `placeholders` | Grow stand-ins; on by default for an id that is not registered. |
| `horizon`, `fill`, `targetY`, `targetX`, `top`, `eye` | A whole-plant framing in screen shares, which stands the camera on the ground as a reference's camera stood. |
| `along`, `span` | How far along a limb a limb view looks, and the metres of bark a bark view frames. |
| `thin` | Metres of radius that a limb view frames: it picks the exposed limb that carries that thickness, so young bark shows. A fork view takes the fork whose limb is nearest that radius. |
| `barkHeight` | Metres above the ground at which a mid-trunk bark view reads the surface, where the photograph shows the surface of one height, such as a column's skin above its corky foot. It goes before the bark zone's own height. |
| `surface` | A limb view of the crown's outside: one foliage mass at the crown's edge against the sky, seen from under the crown's rim, in place of one branch against a plain ground. |
| `limbShare`, `collarColumn`, `limbLie` | A junction photograph read by hand: the share of the frame's height that its limb takes where it leaves the trunk, the column on which its trunk meets the limb, and the degrees the limb rises above level. The first sets the frame alone, so a trunk wider than its part of the frame runs off the left edge. The third chooses the limb: of those at least 0.6 as thick as the thickest, the one that lies nearest. |
| `limbRow`, with `limbShare` | A crown photograph read by hand: the row on which its limb crosses the frame under its leaves, and the limb's share of the frame's height. The crown view then frames the great limb that carries its foliage mass, at its place nearest the mass, on that row. The picture must hold that limb as wood of its own thickness, with leaves over it. |
| `forkRow` | A view up the stem: the row on which the stem's first fork lands. |
| `footRow`, `crownRow` | A view up the stem from a few steps back: the rows on which the ground at the bark and the crown's base land, the crown's at least a tenth of the frame above the foot's. |
| `girth` | A bark view of a great limb that shows the limb itself: the share of the frame's height that the limb's thickness fills, above 0 and up to 1. |
| `leaves`, `roll` | A cut piece framed at its photograph's scale: the leaf lengths that the frame's height covers, with the piece standing on its cut at the lower edge. Then the degrees the camera turns about its line of sight: a quarter turn lays the piece across the frame. A cut piece framed by a `span` turns by the roll too. |
| `piece` | A close view of one placed piece of a class, such as a pine's `bough` or a tuft's `stalk`, in place of a cutting: the outermost piece of the class as the plant places it, square to its face, with only the slab of the plant that holds it drawn. A class names its pieces by their leading words, so `stalk` names every flowering stalk. A plant that places pieces and none of the class fails the picture's rows, since it lacks the part. With `edge`, the camera looks along the piece's side, so an arching piece such as a flowering stalk shows its arch and its hanging heads in profile. With `span`, or `leaves` times the species' leaf length, the view frames that many metres of the piece round the share `along` of its run, as a picture of a frond's mid-section or a stalk's head does. The view looks on the upper side of the piece's plane. With `toward`, it frames the outermost piece that heads toward the camera's side nearly as well as the best one does, as a photograph of one leaf turned to face the lens shows it. |
| `site` | A close view of one site of a class that the plant marks on its surface, read from its bud sites: a `flower`, an `areole`, or a `dormant` bud, which on a saguaro is a nest hole. The view frames the site that faces the camera's side best, looking into it, `span` metres wide; with `edge` it looks along the surface beside it, so a spine cluster stands in profile. A plant that marks sites and none of the class fails the picture's rows. |
| `limbRank` | A limb view's subject as a great limb by its rank, the thickest first, from 1: the view frames that limb across its run from the side of the plane that holds the trunk and the limb, so a cactus's arm or a limb's elbow shows its run, bend and rise, at the slot's `along`, `span` and elevation. A plant with fewer great limbs fails the picture's rows. |
| `turns`, `step`, `columns` | A sheet of turns, each in a cell of its own camera. |

The page posts a `plant-review` message with the form it grew, the plant's drawn height and width (the filled silhouette of the level the view draws, so a part outside that level cannot inflate them), crown base, trunk radius and triangles, each cell's camera, the cutting's size (the piece's own drawn box, on the same rule), and, with `measure`, each cell's measures: the crown box in metres, the plant's filled box, the foliage share, the silhouette, the trunk diameter at 1.3 m, the crown base and the first fork's height.

## How the measures work

- **The outline.** `plantMask` fits a smooth colour surface to the frame's border, above and below the horizon apart, and calls a pixel background when it lies near the surface. A border that is not plain can still separate a plant when the surface models it closely: a sky with no horizon whose fit is at least 0.99 with a residual of at most 24, or a soil below a horizon whose ground fit and residual meet the same bounds. The fit and residual are printed beside the figure, and a ground region outside a soil band's usual share of the frame is flagged, so a bad model is refused or named rather than masked on a guess. A band that the surfaces miss, such as a river or a far bank along the horizon, is cleared where it reaches both sides of the frame, or one side in a thin strip. The ground's own top edge may stand a few rows above the horizon's one straight row, as a ploughed field's clods or a slope lift it: up each column from the horizon, a run of ground, ground in shade or a blend of ground and sky is cleared where the sky stands on it within 0.03 of the frame's height. A run that meets the plant or climbs on past that height is the plant's own foot. Below the horizon a pixel is plant only when it hangs down from the plant above and is not a darker copy of the meadow. Where the outline ends at the horizon or in the ground below it, the stem is then followed down to its foot, row by row, from the stem's own lowest row. The stem is read on the outline without the thin runs along its foot, a horizon line or a strip of grass, as the fit tool cleans them. The stem's column is the middle of the lowest rows' runs nearest the plant's middle, so a speck at the horizon that is wider than the stem does not take its place. The pixels under the run above that keep the stem's colour, against the ground beside them, are the stem's next run, where it covers at least half the run above. A run may widen a little each row, as a root flare does, and the stem's colour follows the rows, as a foot darkens toward the ground. The stem ends where no such run is left, so the plant's height counts from its root collar and not from the horizon or from the grass in front of it. The outline says from which row it was followed. A last row wider than a quarter of the plant is a mass, not a stem, and is not followed. A render's outline comes from its matte, so it is exact. A silhouette photograph is black on white as the drawn matte is, so it is read by the matte's own rule on top of that mask: a texel is plant only where it is darker than half (`halfDarkMask`), so a crown's small gaps stay open on both sides of the figure.
- **The turn's pairing.** Each outline is scaled so the plant's height fills a fixed canvas, with the trunk on its middle column. The overlap of every reference frame with every render fills a table, and the pairing tries every start and both directions, at the video's own step against the renders' step, and keeps the best mean overlap. A frame is covered when its render lies within half a frame's turn of the frame's own angle.
- **The measures of a pair.** Shape and frame overlap, the width profile's error, the gap inside the crown's box with the whole frame's gap beside it, the crown box, and the CIEDE2000 colour difference of foliage and bark (about 2 is a visible step). The crown-box gap is the share of the crown's box that shows background; the frame's gap is the share of the whole picture, which widens with the empty sky a photograph keeps around its plant. The enclosed gap is the crown's own: the background between the crown's outermost plant pixels in each row, which is the sky seen through the foliage. Both pictures count it one way, a texel as sky or as plant. A render's matte also holds each texel's clear share, and the summary prints the gap read by that share beside the figure, since earlier figures were read by it. **A crown-box gap is an envelope figure and cannot judge foliage density**: most of its background is the hollow between the outline and its box, so a row that asks see-through quotes the enclosed gap, and the box figure is printed beside it so the two are never read as one. A bark texture gives the colour difference of the middle of each picture. Every outline figure is read with both pictures shrunk to the work width of 640 pixels, and the summary prints each plant's foot row, the lowest row of its outline, beside them. Each still's cell in the manifest holds the level of detail the page drew it at (`cell.level`: the leaf form, a card level or the far card, with the distance and each level's start), and the summary and each verdict figure name it. The summary names each of the three gaps and gives the photograph's value first: the sky gap enclosed by the crown's outline, which is row 6's figure, the sky share of the crown's box, and the sky share of the whole frame. Each pair states the drawn plant's scale against its photograph's (its share of the frame's height over the photograph's); where that differs from 1 by more than 0.05, the figures read on the frame as a whole, the overlap as framed and the whole frame's sky share, compare a larger or smaller plant and are left out, and the summary says so. The frame-free figures stand. A sky figure compares like with like or is not quoted. A whole view's photograph has no matte: its plant is cut by colour distance from its fitted sky, so a pixel counts as plant from a small cover. The drawing's colour still is read by the same rule, and its gap is row 6's figure. The drawing's matte is stored display-encoded, as the engine's canvas stores it, so the half-dark rule counts a matte pixel as plant only from about three quarters of cover; at a whole view the summary prints the matte's gap after the colour still's, as an instrument figure only. A silhouette is read by the half-dark rule on both sides, the photograph's own bytes being display-encoded too. A gap read by different rules on the two sides is not quoted in row 6. A height share read from a picture's rows, such as the share of the plant's height that the crown's box holds, or the crown's width over its height, is the picture's. A camera that tilts maps rows onto the plant's metres unevenly, so where the camera stands below the plant's middle the summary gives the plant's own share beside it, with the camera's height as a share of the plant's. A photograph's tilt comes from its horizon's row through the view's lens, and a drawing's from its camera; the plant is taken to stand in one upright plane through its foot.
- **The sheath surface's figure.** A junction or crown-foot still of a species whose review data names its sheath target reads both pictures' foot and collar patches at the two ends of the surface's non-green rows, and prints the render's step against the photograph as the row's figure, with the render's step against the authored target beside it as the material check, and the patch areas. A target is an albedo and the render is lit, so a shaded sheath cannot pass it; the photograph is the same lit surface the render draws. Where the photograph's sheath cannot be isolated — its outline is refused — the figure says so as the carrier's limit and leaves the row unjudged. Those views draw their outline as a matte, so the patches stand on the plant alone even where a photograph does not separate from its soil. Only a still at one of those views, with a sheath target in the review data, takes the figure, and no other view or measure changes.
- **The two-dial sweep.** A full round also draws the whole view six times — sparseness 0, 0.5 and 1 by the record's preset and a coarse one — and reads each in order: its connectedness, its height against the record's band, and its crown-box gap. A sparse picture that scatters clumps fails as a generator fault whatever its figures; a coarse picture that thins the plant has mixed the two dials and fails. `--sweeps` draws them alone. The gaps and heights of the sweep are read across the settings and against the record, not as a species verdict; a species whose height calibration lands later moves its heights.
- **The connectivity gate.** The owner's rule is that no piece hangs free at any level or sparseness setting: every leaf, twig, card or bough that loses its parent is joined to its piece or removed. The review reads each still's matte as components at the picture's own width, names each piece that meets nothing inside the frame with its area and box, and fails the picture as a **generator fault** whatever the piece count says. The picture's own width decides: a downscale to the tool's work width can drop a hairline shoot the picture keeps and invent a floating piece, so the work-width read is printed beside it as a second figure and does not decide. A component the frame's border carries may run on outside the picture, so it is not counted as floating. The figure prints the component count beside it, and the sparseness the picture was drawn at where its query names one, so a row read above the record's density is checked at the sparse setting too.
- **The mask check's gate.** A turning video's matte is checked against a colour outline read from each frame: the two outlines' overlap, averaged over the frames the outline can read. A colour outline covering under the plant mask's own 2 per cent subject floor cannot see the plant — a plant that fills the frame leaves the fitted background nothing to find — so those frames are reported as unreadable, and a turn with no readable frame is neither passed nor failed on the check. The gate is 0.6 for a turn on a natural background and 0.9 for a plain-background cut piece, each set from the corpus of 856 turn checks read on 12 November 2026: natural-background turns read 0.717 to 0.978 a frame and sound turns as low as 0.750, so their gate sits 0.15 under the lowest sound turn; plain-background cut pieces read 0.941 to 0.978 a frame, so their gate sits 0.045 under. A turn below its gate fails coverage, and the summary names the turn. A plain-background subject filling under 5 per cent of the frame reports rather than fails, since at that size the overlap is dominated by the boundary band: the holm oak's subbranch turn reads 0.846 with its colour outline at 2.7 to 4.0 per cent and its matte at 2 to 3, where a one-pixel edge costs about 0.15 of the overlap. Where the figure cannot see the subject it reports; it judges only where the subject is large enough and the outline a plant outline.
- **The crown box's spread** at the rubric's eight angles that the video covers, for the reference and the render, against the rubric's band, which the reference's own spread widens.
- **The close views' cameras.** A close view is solved from its subject, with no search over the picture. The page reads the plant's subjects through one interface, `tests/pages/lib/plant-review/subjects.ts`: the trunk and its first fork, the great limbs with their joints, the forks, the crown's lobes, the twig tips, the branch pieces and a leaf. A generator that cannot name a subject reports it as absent, with the reason. The adapter in that file fills the interface from a macro skeleton. A skeleton names no lobes, so the bud sites of one branch stand in for one, in a ball of at most 0.12 of the plant's height in radius. The page reads the plant's placed pieces from its rows (`piecesOfRows`): a piece's parts stand as rows one after another at one socket, it runs from its socket to its farthest vertex, so an arching piece runs to its tip, faces its +Z and has its +X for its side, and its class is its grower's name for it. A plant whose rows are shoots places no piece, so its cut views draw the review cutting. A view whose slot names a `piece` class frames a placed piece instead (`placedPieceShot`). Each view stands its camera so that the subject's points land where its photograph has them (`subject-shots.ts`). The table gives each view's contract. Shares count from the frame's left and top edges. A section view looks straight down the stem at the slot's `barkHeight`, draws the nearest level and only a short slab of the stem below the cut, and lays a flat face over the cut (`cut-face.ts`): a fan from the stem's line to each wood triangle's crossing of the cut's plane, drawn as wood in the skin's mean colour. The wood is a skin with no inside, so without the face the picture looks into an empty tube. The grower holds no flesh, so the face shows the cut's outline, a column's ribs, and no inner structure.

The camera stands above the bole's top and no farther out than half the plant's reach. It stands far enough off that the trunk beside it takes at most half the frame's width, a limb's thickness clear of every great limb where one such stand exists, and with no limb on its line to the trunk ahead. The plant covers at most 0.85 of the frame. A limb's joint in the frame. Where the trunk ends at the bole's top, the camera looks along the thickest limb |
  | `junction` | A great limb leaving the trunk | The collar 0.47 across and halfway down. The trunk to its left and the limb leaving to the right. The limb's base takes 0.35 of the height, in a frame no shorter than 0.9 of the trunk's diameter, or the photograph's own reading from `limbShare` and `collarColumn`. The limb is at least 0.15 as thick as the trunk at the join; a plant with none lacks the part. The camera stands square to the join and looks up 10 degrees |
  | `fork` | A limb dividing into two arms | The joint on the middle column, 0.58 down. The limb below it takes 0.22 of the width. One arm leaves to each side above the joint. The limb sought is 0.27 as thick as the trunk at breast height, or as thick as `thin` names, and never under 0.15 of it; a plant with no such fork lacks the part. The page draws only the wood within 2.5 limb radii of the joint's depth |
  | `bark-base` | The trunk's foot and the ground | The foot 0.72 down. The trunk above its flare takes half the width, whatever its thickness; the drawn root flare is wider than the skeleton's radius. The camera looks down by half its lens and 3 degrees more, so the horizon lands above the frame and the picture holds no sky |
  | `bark-mid` | The bark at mid-trunk | Bark from edge to edge. A frame with no `span` covers at most 0.8 of the trunk's width |
  | `bark-limb` with `girth` | The bark on a great limb | The limb's thickness takes `girth` of the height. The limb crosses the frame. Wood as thick as the limb covers 0.85 of the middle box, and leaves at most a quarter of it. The page draws the plant from 1.5 limb radii in front of the limb's centre line, so nothing hangs between the lens and the bark |
  | `trunk` | The bole from its foot to its top | The foot 0.92 down and the bole's top 0.2 down, from eye height |

  A solve takes the subject that fits its photograph: the thickest limb that leaves at 25 degrees or more, a great limb's fork whose thinner arm has half the limb's radius. It then takes the first one that no trunk or great limb hides from the camera. A camera that looks up the trunk walks round it in steps of 15 degrees to a stand clear of the limbs. A slot's `distance` still moves the camera along its line of sight, and the contract is then checked on the camera that drew. The other close views find their subject in the skeleton and the shoot rows, and weigh cameras round it on a coarse grid (`close.ts`): one branch with its side branches, a twig with its end clusters, a limb's hanging strands, a tuft's flowering heads, and a bark view that names a `thin` radius. A tuft whose crown leaves no main stem has no limb for the junction view, so its junction picture stands at the crown's foot. The page posts each view's subject with its facts, and the summary lists it.
- **The subject check and the void picture.** The page projects each point of a solved view's contract through the camera that drew. A point must land in front of the lens, inside its frame box and at its contracted size. The page posts the result with the contract's regions: the parts of the picture that must show plant, or open ground. Where the run drew a matte, the tool reads the plant's cover in each region (`subject-check.ts`). Every solved view also draws a picture of the plant's parts in flat colours from the same camera (`stills/<name>-parts.png`): wood red with its radius in the blue channel, foliage green, extras green and blue, on white. The plant shader draws it with the colour picture's own cut edges and layers, so it says which part covers each texel. The regions are read from that picture, and a region can name wood, with a least and a greatest radius, or foliage: a limb's bark must be wood as thick as the limb, and leaves may cover only a small share of it. A matte is not used for a close view: close up it blends every level's soft coverage and reads fuller than the colour picture. A wood area takes wood between 0.75 and 1.4 of its subject's radius, so neither a branch nor the trunk stands in for a limb. A limb's join also asks for unbroken wood between the bark and the limb, a crown view asks for the branch its leaves hang on and for sky at both sides of the lobe, and the view under the crown asks for its great limb at two places along it. The tests hand the check pictures made by hand that show another thing than the subject, and each must fail. A solved picture whose regions were not read counts as not checked. A close picture is void too when its page measured its subject at under 0.01 of the frame, or when the page drew the same picture for another photograph that was asked for differently; a whole view is void when the plant covers all of its frame or none. A picture is void when the view cannot name its subject, when a point misses its box, or when a region fails after the solve said it could take no clear stand. A region that fails after the solve held is the plant's fault: the camera holds the subject's place and the plant hides or lacks the subject, so the tool fails the picture's rows with each region's figure (`subjectFault`). A region marked `report` gives its figure and judges nothing: the wood above the fork in the view up the trunk is one. The summary prints every region's cover for each solved picture, and the coverage list gives a failed picture the status `plant fault`, which counts as read. Where the plant itself has no such part, the page posts that the plant lacks it, and the tool fails the picture's rows in place of a void; a ground plant, which draws no wood, keeps the void for a wood view, since its slot named the wrong view. The tool reads no figure from a void picture. It lays the picture on the sheet beside its reference with the word VOID, lists the reason in the summary and the coverage list, and counts the file as not compared. A void picture is a fault of the tool's camera or of the file's mapping to a view. It never passes or fails a row. The sight-line test of a solve knows the trunk and the great limbs only, so the picture of the parts is what catches a spray of leaves or a thin branch across the subject.
- **The whole view's stand.** A framed whole view is stood on the points the plant draws at the level the view draws (`whole-stand.ts`). The horizon's row sets the pitch. The camera stands where the highest drawn point lands on the asked top row and the lowest on the asked foot row, or at the asked eye height where the picture names one. A plant wider than its photograph's share of the frame moves the camera back, and the foot stays on its row. A photograph whose outline ends at the horizon on a mass too wide to be a stem has lost the plant's foot below it (the plant-targets tool's own test, `footLost`), so its last row is the horizon and not a foot: the view then names no foot row, and the camera stands where the plant takes the photograph's share of the width with its top on the photograph's top row; a width redraw widens that share by what the drawing measured. Thin stalks standing in grass of their own colour lose their foot so too. A whole view's near plane stands closer than half its eye's height, so a camera near the ground draws the ground to the frame's lower edge. A redraw that corrects the drawn width moves the camera out the same way, never along its line of sight, which would lift the camera and drop the foot off the frame. It moves the camera in no nearer than the stand on the asked rows: a nearer camera draws the plant taller than its photograph's share of the frame. So a plant narrower than its photograph keeps the stand on its rows, the run does not redraw it, and its width error is the plant's own; a plant that stood back for its width, whose drawn edges stand inside its points as a fern's fading tips do, comes in as far as its rows. A second redraw builds on the first's scale. The ground hides what grows under it, so a point of wood under the ground is left out, but a leaf point under it counts at the ground: a blade that dips through the ground is drawn down to where it meets it, which a low camera near the plant sees far out in the frame. Last, the camera stands back as little as holds every drawn point inside the frame. It searches for that distance, since a step by the share a point runs over overshoots: close up, the near side of a broad crown grows in the frame faster than the plant. The unit tests hold the stand for seven habits against five framings from every side, and check that a stand held back by the frame keeps one edge of the plant on the frame's margin.
- **The whole view's framing check.** A whole view or a silhouette whose render drew a matte is checked before any figure is read. A render whose plant runs to an edge of the frame that the photograph's plant stands clear of is void, with the edges in the reason. The plant's box must also match the photograph's within a fifth, in height or in width. A render smaller in both, or larger in both, is void, with both sizes in the reason. The plant's place in the frame is not compared, because a photograph's outline can cut its foot short and a render's can run to the frame's lower edge.
- **The species' review data.** A species' slot file holds two reserved keys beside its slot queries (`review-data.ts`). `_habit` names how the plant stands where that changes the outline's reading: `clump` for several bare stems from one stool, whose crown starts where the rows fill with foliage. `_pictures` names single pictures. A picture with a `standing` of `second-form`, `reference-limit` or `stand`, and a `reason`, does not judge the primary plant. A `stand` is drawn, set beside its reference and not measured; its `count` and `spacing` say what the page must plant once it can. A picture with an `outline` reason has outline figures that are void, and keeps its color figures. The run reads these keys from the species' own file whether or not `--slot-query` names it.
- **The cut pieces of close stills.** A still of one branch or one twig on a plain ground is drawn as a cut piece, as the studio stills are. It is framed at the photograph's own scale in leaf lengths and stands on its cut at the frame's lower edge. A branch lies across the frame, as its photograph lays it.
- **The studio pieces.** A cut piece is fitted to the points it draws: its parts', and the vertices of its shoot rows, which draw the leaves of a piece cut from an instanced plant. A studio still or a cut piece's turning video also gives the rows its piece's top and foot stand on, measured from the picture. The page then puts the piece's highest point on the top row and its lowest on the base row, or on the frame's foot where the picture's piece runs off it.
- **The wind's motion.** In six height bands of the plant, base first, the share of the outline that changes from frame to frame, averaged over each clip.

## Limits

- A picture with neither a plain border nor a fitted sky or soil, such as bark or the inside of a crown, has no outline; its row shows the pictures and the colour figures alone. A close view of the wood (`junction`, `fork`, `inside`, `trunk`) takes a plain background only: no sky or ground is fitted to it, and none colours its render's background.
- The coverage list gives each file one status. `compared`: a figure was read. `drawn`: the picture was drawn and its subject checked, and the standard states no figure for its view (`below`, `limb`, `crown-underside`, `inside`, `junction`, `fork`, `trunk`), so the eye judges it. `unmeasured`: the picture gave no figure where its view has one, or no check confirmed its subject, which is a fault of the tool. A `drawn` file counts toward a complete run and passes no row alone. An `unmeasured` file does not count. The verdict lists the `drawn` files under `coverage.drawn`, and the ledger names them under their species.
- A whole view's drawn width is measured from its matte. A picture whose plant runs off both side edges takes its width share from the camera's stand instead, because the image can hold no plant wider than the frame.
- A turning video is taken to turn at a steady rate over its arc.
- A turn's renders are drawn as sheets of cells. Each cell draws at a still's size, and its outline is measured at the same work width as a still's and the video's frames, so a turn's frame and a still from the same camera give the same figures. The measured cells draw no shadows: the matte carries the plant alone, so its colour partner must too, and a cast shadow on the backdrop would be counted as plant. A sheet holds at most eight million pixels.
- A sheet draws a cut piece at the nearest level. A cut piece has no card levels, so a sheet's
  smaller cells would otherwise switch its foliage to cards that hold nothing, and the piece would
  vanish from the sheet.
- A stand-in's nearest level has no shoots: it shows its wood and its cards up close.
- A ground plant such as a sedge or a hosta draws its whole body as merged foliage, with no wood. A
  view that asks for the wood alone keeps that foliage, since the plant has nothing else to show,
  and a view up the stem stands at a low eye beside the plant instead of at a person's eye height,
  since the plant has no stem to look up. A bark view of such a plant is void: its slot must name
  the view of the surface that the photograph shows.

## The verdict and the ledger

A run writes `verdict.json` into its folder. The file holds one entry for each of the twelve rows
of the [plant review standard](../../../.dev/plant-review.md): `pass`, `fail`, `void` or `unjudged`,
the pictures the row rests on, each figure with its band, who judged the row, and the run and commit
the pictures were drawn at.

- The tool passes no row. For the rows whose band the standard states, it writes a proposal under
  `proposed`: figures in band, or out of band with the figures outside. Row 6's band runs from 0.02
  below the reference's sky gap to 0.05 above it, on every whole view. Rows 8 and 10 take a color
  difference of 3 or less. A row with only a proposal is `unjudged`. The tool fails row 12 alone
  when a picture draws a piece that hangs free.
- The tool writes the figures of rows 4 and 9 with no band, since the standard states none, and
  leaves those rows and the rows the eye judges as `unjudged`.
- A row whose pictures are all void is `void`. A row with some void pictures names them beside its
  evidence.
- Row 6's figure is the sky gap enclosed by the crown's outline. The crown box's sky share does not
  judge the row, since it measures the taper of a plant that does not fill its box.
- A picture that the review data sets aside is listed under the row's `setAside`, with its reason.
  It is not among the row's evidence, and its figures are not among the row's figures. A picture
  whose outline is void is listed under `outlineVoids`. Every `_pictures` entry cites its `ruling`, and the verdict lists them all under `rulings`, which the ledger prints under the species.
- Row 2 holds a cut branch's four density figures where a run measured them (`cutBranch` on the
  still's result): the wood per tip and the tips per area within a quarter of the photograph's, the
  share of fan joints at most a tenth above it, and the kinks at least half of it. Lengths are in
  piece lengths. A figure that either picture cannot give is null and is left out, and so are the
  wood per tip and the kinks unless `cutBranch.bare` says the piece carries no leaf. The reviewer
  judges the row.
- A picture of a part that the plant does not have is listed under the row's `lacking`, and the
  tool fails the row on it. The species' reference set holds the photograph, so the species has the
  part, and a plant grown without it is wrong. A void is different: the plant has the part and the
  camera did not frame it.
- A picture with no subject check is listed under the row's `unchecked`. A solved view is checked
  by its contract, and a whole view by the crop and size checks. No row passes on unchecked
  pictures alone.
- A reference picture of the row that the run did not compare is listed under `notCompared`.
- Rows 1 to 3 name the run's picture of the wood alone, `views/skeleton.png`, among their evidence.
  A run that draws every still draws that picture too. None of those rows passes without it.
- `balance` holds the plant's balance through the eight angles of the standard's coverage rule. Its
  figures are the spread of the crown box's width and of its height over the whole-plant turning
  video, each against its band. The tool fails the balance where a spread leaves its band.
  Otherwise the balance waits for a reviewer, like a row.
- A reviewer edits the file: sets a row's `verdict`, sets `judge` to `reviewer`, and gives a
  `reason`. A pass also needs `review`: the reviewer's name, the day as year, month and day, and
  the path of the review file that holds the reading. That file must exist and must name the row
  as `row 6`, or name the `balance`. Row 11 names its `neighbour`. A run compared again keeps
  every row a reviewer judged and refreshes the rest.

`bun run plants:ledger <path...>` reads the verdict files of run folders and prints the species by
row table and the total. A path is a run folder or a folder of run folders.

```sh
bun run plants:ledger /tmp/plant-renders
```

The table always holds the standard's twenty species, and the total's base is always 240 rows. A
species with no verdict counts as none of its twelve. Under each species the command prints how many
pictures each row lost: not compared, void, of a part the plant lacks, set aside, or with no
subject check. A species is done when its twelve rows and its balance pass and its run compared
every reference file.

The command ends with status 1 and prints no total when a verdict is unsound. A verdict is unsound
in each of these cases:

- A row is missing, a judged row names no judge, or a fail or a void gives no reason.
- A figure names another run than the file's.
- The file is not `verdict.json` in its run folder, or the folder holds no manifest, or the
  manifest names another run, commit or species.
- The commit is not a commit's full name.
- A picture the verdict names is not in the run folder.
- A pass is the tool's, or lacks its reason, reviewer, day or review file.
- A pass rests on no picture, only on void pictures, or only on pictures with no subject check.
- A pass stands on a run drawn from a tree with changes, or on a run that did not compare every
  reference file.
- A row passes though the plant lacks a part its photograph shows.
- Two verdict files name one species, or a file names a species outside the twenty.

Quote a count of passing rows only from this command's output.
